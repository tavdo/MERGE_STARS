# MERGE visual continuity

Preserve the existing Museum experience when implementing functionality. A new
feature is not authorization to replace the entrance, city, House interiors,
personal-museum route, logo or application theme.

- `lib/company-identity.ts` is the sole company identity source. Use the existing
  `CompanyMark`, `CompanyWordmark` and `MergeWindowChrome`. Do not invent a logo,
  tagline or separate brand header for a new tool.
- Keep the official source pixels and logo viewport unchanged. Approximate marks
  baked into reference artwork are not alternate company logos. Presentation
  overlays may use the canonical asset; preserve the original source files.
- Keep closed gate → opening gate → existing city → House → category showcase.
  The city My Museum action opens the existing Brand Museum, not a layout study.
- Architectural layout tools are optional and explicitly identified as studies.
  Keep their entry collapsed; do not make them the default personal House.
- Room palette preferences apply to the room study only, never to the site's
  common black/silver/gold frame.
- Keep working draft, Fit, catalog, source/history and financial boundaries.
  Describe unavailable CORE/provider capabilities truthfully.
- Review the change against the current request and existing routes before
  packaging. Preserve image hashes and run the applicable existing checks.

An explicit new user request may change the relevant design requirement. Do not
infer a redesign from a request to fix or connect existing functionality.
